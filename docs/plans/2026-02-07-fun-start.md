# Funcode: AI-Friendly Version Control System

**Date:** 2026-02-07  
**Status:** Implementation Started

## Overview

Funcode is a version control system designed specifically for AI agents. It provides:

1. **Undo/redo for AI changes** - Revert AI edits while preserving user work
2. **Track AI contributions** - See what AI changed vs what human changed
3. **Review before commit** - Stage AI changes separately for review
4. **Parallel explorations** - Let AI try multiple approaches

## Design Decisions

| Aspect | Decision | Rationale |
|--------|----------|-----------|
| **Storage directory** | `~/.funcode/` | Keep separate from project |
| **Patch format** | Unified diff | Standard, human-readable |
| **Git integration** | Completely separate | Don't touch user's `.git` |
| **Conflict handling** | AI suggests resolution, auto-applied | Smooth flow |
| **User confirmation** | Not required (can undo later) | Trust AI |
| **Session persistence** | Persistent (explicit delete) | Keep history |
| **New file revert** | Delete the file | Clean revert |
| **Binary files** | Ignore | Text-only |
| **Branching** | Explicit switching | Future enhancement |
| **Multi-agent** | File locking + session metadata | Agents can read context |
| **Runtime** | Bun only | Simpler FFI, better performance |
| **Package name** | `@byfungsi/fun` | Monolithic package |
| **API style** | Fully async | Promise-based |

```

└── sessions/
    └── {sessionID}/
        ├── manifest.bin            # Session metadata, version tree
        ├── files.bin               # FileState for each tracked file
        ├── locks.json              # Active file locks
        ├── originals/              # Original file contents (content-addressed)
        │   ├── ab/
        │   │   └── cdef...zst     # Compressed, keyed by content hash
        │   └── ...
        ├── patches/                # Stored patches (unified diff, compressed)
        │   ├── 0001.diff.zst
        │   └── ...
        └── versions/               # Version metadata
            ├── 0001.json
            └── ...
```

## Core Workflows

### File Write Flow

```
1. Agent tool intercepts file write
2. Before write: read current file content
3. Check for conflicts: preCheck(file, agentId)
4. If conflict: AI analyzes and resolves
5. Write happens: write_file(path, new_content)
6. Track change: trackChange(file, before, after, agentId)
7. Funcode generates diff, stores original if new, creates version
```

### Conflict Resolution Flow

```
preCheck() returns conflict
        │
        ▼
AI receives: { expectedContent, actualContent, diff }
        │
        ▼
AI suggests: accept_human | revert_to_expected | merge(content)
        │
        ▼
Resolution auto-applied, AI can proceed
```

### Multi-Agent Coordination

```
1. Agent reads session metadata (active locks, recent changes)
2. Agent calls preCheck() before editing
3. If locked by another agent: wait, skip, or inform user
4. preCheck() acquires lock
5. Agent writes file
6. trackChange() stores patch and releases lock
```

## TypeScript API

```typescript
// @byfungsi/fun

// Session management
export function createSession(projectPath: string): Promise<Session>;
export function loadSession(sessionId: string): Promise<Session>;
export function loadOrCreateSession(projectPath: string): Promise<Session>;
export function listSessions(projectPath?: string): Promise<SessionInfo[]>;

// Session class
export class Session {
  readonly id: string;
  readonly projectPath: string;
  
  // Core operations
  trackChange(opts: TrackChangeOptions): Promise<Version>;
  revertFile(file: string, toVersion?: number): Promise<void>;
  revertAll(toVersion?: number): Promise<void>;
  
  // Queries

  getStatus(): Promise<StatusInfo>;
  getHistory(limit?: number): Promise<Version[]>;
  getDiff(from: number, to: number): Promise<string>;

  // Conflict handling
  preCheck(file: string, agentId: string): Promise<PreCheckResult>;
  resolveConflict(file: string, resolution: Resolution): Promise<void>;

  resolve(file: string, resolution: Resolution): Promise<void>;
  revert(file: string): Promise<void>;
  cleanup(): Promise<void>;
}
```

## Performance

### Why Zig + Bun FFI

| Operation | Pure TypeScript | Zig via FFI |
|-----------|-----------------|-------------|
| Myers Diff (100KB) | ~50-100ms | ~5-15ms |
| Blake3 Hash | ~2-5ms | ~0.1-0.5ms |
| Zstd Compress | ~10-20ms | ~2-5ms |
| FFI overhead | N/A | ~0.1ms |

**Zig is ~5-10x faster for CPU-bound operations.**

The diff algorithm is the hot path - happens on every file edit. For AI agents editing many files, this performance difference is significant.

## Inspiration

- Learned from OpenCode's snapshot/undo implementation
- OpenCode uses Git tree objects without commits (clever but has downsides)
- Funcode uses simpler approach: store originals + unified diffs
- Separate from Git entirely to avoid complexity

## Key Insights from OpenCode Analysis

1. **Edit tool uses fuzzy matching** - Handles AI's minor whitespace/indentation mistakes
2. **LSP validation post-write** - Catches syntax errors, returns to AI for fixing
3. **Session-based history** - History tied to conversation session
4. **Git tree objects** - Efficient but couples to Git, orphaned objects issue

Funcode takes a simpler approach:
- Store original files directly (content-addressed, compressed)
- Generate unified diffs (standard format, human-readable)
- No Git dependency
- Clean session lifecycle (delete session = delete all data)
